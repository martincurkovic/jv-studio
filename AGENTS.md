# Agent notes for jv1010editor

Cold-start context for AI agents, and the place to record findings. It exists to stop you "fixing" things that look like bugs but are
deliberate, and to say what was MEASURED on a real JV-1010 versus read from the manual versus guessed. Human docs: `README.md`. Plans:
`dev_docs/roadmap.md`. The sibling project AKAISDS (`~/Development/AKAISDS`, same owner) is where the UI conventions and many hard-won
MIDI lessons come from; its `AGENTS.md` is worth reading before building anything similar.

## House rules

- Keep `.gitignore` current as files appear (the owner asked): build output, caches, local captures (`*.syx` is ignored except `tests/fixtures/`), editor folders. Commit `uv.lock`
  and the generated `data/parameters.json` and diagrams.
- Don't commit, branch, tag or push unless asked. The owner handles git. Ask before anything outward-facing.
- **Real hardware:** read "Hardware safety" first. Back up before writing. Close DAWs and MIDI monitors.
- Keep user-facing text short (a line or two). Detail goes in the log.
- **Record findings here, tagged by how you know them:** `[manual p.N]` read from the Owner's Manual, `[hardware YYYY-MM-DD]` measured on the owner's
  JV-1010, `[guess]` neither. Dated. Move a `[guess]` to a measured tag when it is proven; delete it if it is disproven.
- Tests: `uv run pytest` (fast). Never let a test touch real MIDI ports or the user's `~/.jv1010editor`.
- UI target: the same theme and behaviour as AKAISDS (PySide6 6.12, dark/light/system, collapsible cards, knobs, draggable envelope graphs).
  Copy and ADAPT AKAISDS code (the owner chose this over a shared package); both are GPL-3.0, so that is fine.

## Layout

- `src/jv1010editor/core/`: Qt-free. `sysex.py` (framing), `params.py` (the table and value I/O), `patch.py` (a patch and `.syx`), `midi.py` (ports and a
  SysEx connection over python-rtmidi), `unit.py` (reads, verified writes, single-parameter edits), `memory.py` (the whole user memory as a block list), `backup.py` (whole-unit backup/restore
  and the per-slot backup files), `stock.py` (USER patch vs the factory list), `validate.py` (a patch vs the table's ranges),
  `midi_diagnostics.py` (loopback and hardware detection), `loopback_report.py`, `app_config.py`, `debug_log.py`, `diagnostics.py`.
- `src/jv1010editor/data/parameters.json`: GENERATED by `tools/extract_params.py` from the manual. Don't hand-edit it: fix the extractor and re-run.
- `src/jv1010editor/ui/`: `theme.py` + `style.qss.template` (colours live ONLY in the palettes), `main_window.py`, `settings_dialog.py`, `midi_session.py`,
  `unit_worker.py`, `unit_dialogs.py` (pick a USER slot; pick what to restore), `section_card.py`/`qt_helpers.py`, `loopback_results_dialog.py`, `diagnostics_ui.py`, `help/diagrams/` (made by `tools/make_diagrams.py`, needs `rsvg-convert`).
- `tests/fakes.py`: fake rtmidi ports, a loopback cable and `FakeJV1010` (identity, RQ1/DT1 for the temporary patch, the 128 USER patches and every system/performance/rhythm block; `gm_mode=True` makes it ignore RQ1,
  `ignore_writes=True` makes it store nothing).
- `manual/` is git-ignored: Roland's `JV-1010_OM.pdf` stays out of the repo.

## The app shell (phase 1)

- Adapted from AKAISDS (copy-and-adapt, same theme and conventions): `ui/theme.py`, the stylesheet, `section_card.py`, `qt_helpers.py`, the Settings dialog's shape,
  `loopback_results_dialog.py`, `diagnostics_ui.py`, crash handlers. Colours are palette keys (`${key}` in the template, defined in BOTH palettes); a missing key raises at startup.
  Generated chevron icons go to `~/.jv1010editor/generated_icons`, not the app bundle.
- **`MidiSession`** (`ui/midi_session.py`) owns the one `MidiConnection`. A diagnostic must open the same ports itself, and two opens of one port conflict, so it runs inside
  `session.paused()` (close, borrow, reopen). Tests give the session a `connection_factory` over `FakePorts`.
- **`MidiConnection.close()` takes the same lock as `send()`**: AKAISDS crashed (SIGSEGV) deleting an rtmidi port while another thread was inside `send_message`.
  Port LISTING never raises (macOS CoreMIDI sometimes refuses a new client right after a relaunch): it logs and returns no ports.
- Request/reply keeps ONE request outstanding (`MidiConnection.request` drains stale replies first, then waits for the first reply `accept` likes, ignoring others).
- **Hardware detection sends only an Identity Request and, if a JV-1010 answers, ONE RQ1 of the temporary patch's common block** (its name). No write of any kind. Silence stops it
  there: never send into silence. A unit in GM mode answers the identity request but not the RQ1 (the manual says it ignores RQ1/DT1 there): reported as such.
- Diagnostic timeouts are read at CALL time (`midi_diagnostics.RECEIVE_TIMEOUT`), so tests shorten them with `monkeypatch.setattr`.
- Config: `~/.jv1010editor/config.json` (`midi_input_port`, `midi_output_port`, `theme`, `collapsed_cards`); log: `~/.jv1010editor/jv1010editor.log`; native crashes: `crash.log`.
  `tests/conftest.py` redirects all three to a temp folder and forces `QT_QPA_PLATFORM=offscreen`: a test must never touch the real folder.
- **`JV1010Unit`** (`core/unit.py`) is the only code that talks request/reply to the unit: `read_block` accepts only a reply naming the requested address AND size, retries a timeout
  once, then raises `UnitError`; `write_patch` sends packets <= 128 bytes at least 20 ms apart and (by default) reads the patch back and compares; `write_param` is the live-edit
  path (one small DT1, no read-back). Reads never write. `Patch.minimum()` is a VALID blank (all-zero bytes are not: no name characters, tempo 0).
- **`UnitWorker`** (`ui/unit_worker.py`) is ONE persistent `QThread` with a FIFO of jobs (`temporary`, `user` n, `names`), results as signals; tests drive it with `process_pending()`.
  While it is busy the window disables Settings and every read (Settings closes and reopens the connection). Don't go back to a thread per action.
- **The main window is READ-ONLY for now**: Read Temporary Patch, Read USER Patch Names (double-click reads that patch), a parameter tree, Save as `.syx`. Every read is checked with
  `validate.out_of_range`: a value outside the manual's range is shown in amber and logged as a WARNING (`UnitWorker: temporary: ...`). **On the first reads from the real unit, read
  those log lines: each is either a mistake in the manual-derived table, in the extractor, or a value the manual doesn't describe. Record what you find under "Findings log".**
- "Share on GitHub" in the loopback results is hidden while `loopback_report.ISSUES_URL` is None (there is no public repository yet).

## The patch editor (phase 3, first cut)

- `ui/patch_editor.py` builds one tab per block (Common, Tone 1-4) FROM THE TABLE: `core/groups.py` says which card a parameter is on (prefix rules; `tests/test_groups.py` fails if a table
  parameter lands on no card, so a re-extracted table can't silently drop one). A string is a line edit (12 chars), a choice/label list a `ChoiceCombo` (JV-1080-only choices are not offered,
  but a value the unit holds that isn't offered is shown, never hidden), anything else a `ValueSpinBox` that shows the unit's own text (note names, +12, L30, OFF) via `params.format_value`
  and parses it back. Wheel events only act with focus. Pages are built when their tab is first shown (building all five cost ~2.5 s per window in tests).
- **The editor edits a `Patch` IN PLACE (the window's working copy) and never talks to the unit**; it emits `param_committed(block, key, tone, value)` once per user edit (a spin box on a step
  or Enter, a combo on `activated`, a name on `editingFinished`), never while showing a patch (`_loading`). The window owns the rest.
- **Live edit rule** (owner's: live UI, MIDI on release): an edit becomes a `write_param` job (a single-parameter DT1 to the TEMPORARY patch, then a read-back of that parameter's block) only
  when `_temp_synced`: the shown patch was read from the temporary patch, or was sent with Send to Temporary Patch and unchanged since. Otherwise the unit is playing a different patch and a
  lone parameter would make a hybrid, so the hint says "Send to Temporary Patch to hear your edits". A failed live write switches live sending off with ONE warning (queued edits fail too).
  **Single-parameter DT1 on a patch parameter is still not proven on the unit** (the manual's own example is a performance parameter); Revert and the working copy mean nothing is lost if it isn't.
- Edits are not stored anywhere until Write to USER (backup first) or Save as .syx. Reading or opening another patch over edits asks first (default No). "(edited)" marks the label.
- Not done: draggable envelope graphs, EFX parameter names per type (the 12 `efx_parameter_n` are plain numbers: the manual's per-type tables are not extracted), wave names (Wave Number is a
  number), Undo (only Revert), a patch list that edits USER slots in place.

## The parameter table

- `tools/extract_params.py` reads the manual with `pdftotext -layout` (poppler) and self-checks every block: its parameters must cover bytes 0..size-1
  exactly once, with the size from the manual's own "Total size" line. A parser slip fails loudly instead of shifting an offset. `--check` verifies without writing.
- Offsets in the JSON are DATA indexes (7-bit address bytes folded: `01 00` = 128). Tone parameter `reverb_send_level` is at 128, so it lives in a
  second packet when sent.
- Values the manual puts in angle brackets (`<...>`) belong to the JV-1080/2080/XP and are IGNORED by the JV-1010: `jv1080_only` on a parameter,
  `jv1010: false` on a choice. A UI should hide or grey them. [manual p.74]
- Footnote value lists become `choices` when they have exactly one entry per value of the range; Patch Category's list is 39 entries of a 0-127 range
  (`(0-38)`), so a UI must offer only those 39.
- Roland's note names: note 0 is C-1, so **60 is C4** (the manual's "C-1 - G9"). This differs from AKAISDS's S3000XL convention (60 = C3): don't share that code.

## Protocol facts

All `[manual]` unless tagged. Page numbers are the printed ones in the MIDI Implementation chapter.

- Exclusive: `F0 41 dev 6A cmd ... sum F7`. Roland ID `41`, **model ID `6A`**, **device ID fixed at `10`** (not configurable). RQ1 = `11`, DT1 = `12`. [p.71-72]
- Checksum: the low 7 bits of (address + data/size + checksum) are 0. Worked examples (used as tests): DT1 `F0 41 10 6A 12 01 00 00 28 06 51 F7`; RQ1
  `F0 41 10 6A 11 10 02 12 00 00 00 00 19 43 F7`. [p.86-87]
- **RQ1 must use a block's own fixed start address and size**; the unit answers nothing else. Patch common = 0x4A bytes, each patch tone = 0x81 (129). [p.71]
- **DT1 larger than 128 bytes must be split into packets of <= 128 bytes, >= 20 ms apart.** A tone is 129 bytes, so it goes as 128 + 1 (the second packet at
  address +01 00). The 2015 jv1010tool sends it whole; whether the unit tolerates that is unmeasured. [p.72]
- RQ1/DT1 are not received in GM mode. [p.71-72]
- Identity: request `F0 7E 10 06 01 F7`; reply `F0 7E 10 06 02 41 6A 00 05 00 00 00 00 00 F7` (family `6A 00`, family number `05 00`, then 4 revision bytes). [p.73]
- Addresses: Patch Mode Temporary Patch `03 00 00 00`; User Patch USER:001..128 `11 00..7F 00 00`; within a patch: Common `00 00`, Tones `10 00`, `12 00`, `14 00`, `16 00`.
  Temporary Performance `01 00 00 00`; performance-mode temporary patches `02 0n 00 00`; User Performance `10 00..1F 00 00`; System `00 00 00 00`. [p.74]
- `#`-marked values are nibbled: two bytes, high nibble first (ABH is sent as 0AH 0BH). Patch Tempo and Wave Number are. [p.74]
- Patch names use ASCII 32-125 (the manual's table stops at `}`); `core/params.py` maps anything else to a space. [p.87]

## Cross-checks done

- 2015 `Ahlzen/jv1010tool` (MIT, JavaScript) vs the manual, 2026-10-13: every patch common/tone offset and nearly every range agree. Differences: EFX Control
  Depth 1/2 are 0-126 (manual) not 0-127; Velocity Range Lower/Upper are 1-127 (manual) not 0-127. Its two-byte getter has an operator-precedence bug
  and its accessors attach to the wrong prototype. Use it as a protocol reference only; the manual wins.
- JV-1080 projects looked at and rejected 2026-10-13: `RoberNoTson/JV1080lib` (no licence, Linux/KDE4/MySQL), `emm-ess/jv1080` (no licence found, barely started),
  `sonic-codex/jv1080-sysex-manager` (MIT, but its YAML addresses don't match the manual: temp patch common at `01 00 20` with 14 parameters).
- JVTool (BSD, 2002-03) targets the JV-80/880 generation (model byte `46`): unrelated parameter layout.

## Hardware safety

The owner's S2000 lost its hard disk boot to echoed sysex and misc-register reads (AKAISDS, 2026-10-10). The JV-1010 has no disk, but the habits carry over:

- **Close DAWs and MIDI monitors** before talking to the unit; a MIDI loop that echoes its own replies back makes it execute them as writes.
- **Writes go to the temporary patch first.** Writing a USER patch is a deliberate, confirmed action with a backup of what it replaces.
- Request/reply code keeps ONE request outstanding, accepts only the reply that names what it asked for, and gives up after a few unanswered reads. Never send into silence.
- Every write is followed by a read-back that must match; never trust the absence of an error.
- Never invent a write path the manual doesn't document. Only the parameters in `parameters.json` exist.
- **The only writes in the UI** (all run on `UnitWorker`, all read back): *Send to Temporary Patch*; *Write to USER...* (a slot dialog; the slot's current patch is read and saved to
  `~/.jv1010editor/backups/USER-nnn-<time>.syx` FIRST and nothing is written if that fails; the first change of a session offers a whole-unit backup); *Restore Unit...*.
  A new write path needs the same: backup, read-back that must match, a confirmation.
- **Whole-unit backup** (`core/memory.py`, `core/backup.py`): one RQ1 per block of `memory.plan()` (system 18 blocks, 32 performances x 17, 2 rhythm sets x 65, 128 patches x 5 =
  ~1,300 requests, ~98 KB), saved as ONE `.syx` of the DT1s as the unit sent them (so `patch.parse_syx` reads a single patch out of it too). Restore checks the backup holds every
  block of the chosen sections BEFORE writing, writes block by block (<= 128-byte packets, >= 20 ms apart), reads each block back, and stops at the first mismatch. **System
  settings are written last and are unchecked by default**: a restore of patches must never change MIDI channels or the sound mode. Cancel stops between blocks and says how far it got.
  The temporary areas (`01..`, `02..`, `03..`) are edit buffers and are not backed up. **Not yet run on the unit** (see the checklist in `dev_docs/roadmap.md`).
- **Stock check** (`core/stock.py`): the manual's Patch List (name + key assign for USER:001-128, in `parameters.json`) against what the unit holds. A name match is a HINT, not proof.

  256-byte SysEx messages): the Identity Request was answered and parsed (family 6A 00, number 05 00, **device ID 16 (10H), software revision 00 00 00 00**), and the one
  read-only RQ1 of the temporary patch's common block (0x4A bytes) was answered: patch name "St.Concert" (the factory USER:002). So RQ1/DT1 framing, the checksum and the

- **A 256-byte interface is enough.** The largest message either way is a patch tone: 129 data bytes + 11 bytes of framing = 140 (our own packets are <= 139). Every block in
  the table is <= 129 bytes, so no message ever exceeds 140 bytes (`tests/test_message_sizes.py` guards it). Never ask for several blocks in one RQ1 (the unit refuses
  anything but a block's own address and size anyway), and keep DT1 packets <= 128 data bytes.
